# 小说版开发范围

## 单一方案

用户条件 → SearchPlan（远端 / 本地）→ NovelProvider 分页获取 → ID 去重 → 本地筛选排序 → 按需加载正文。

不预建公共或个人作品库，不要求用户维护数据库。后续只做有容量和有效期的自动缓存。

## 模块

| 目录                  | 职责                                         |
| --------------------- | -------------------------------------------- |
| `src/domain`          | 与接口无关的作品和正文类型；缺失统计为 null  |
| `src/features/search` | 条件分配、累计结果去重、筛选和稳定排序       |
| `src/providers`       | 获取作品列表与正文的接口；当前只有 demo 实现 |
| `src/features/reader` | 阅读界面、排版与主题                         |
| `src-tauri`           | 原生宿主；后续承接登录、网络和短期缓存       |

前端提供响应式界面；纯逻辑可独立测试。真实请求通过 Rust 适配层处理，登录凭据留在系统安全存储，不进入前端存储、日志或仓库。缓存方案在真实接口验证后确定，当前不引入 SQLite。

## 当前可运行

- 使用 6 篇虚构小说演示标签搜索，每次获取 3 篇。
- 将关键词、匹配模式、日期范围归入远端条件，复杂过滤和排序归入本地条件。
- UI 提供标签完全匹配排除、标题/简介关键词排除、收藏/浏览/字数下限、三种降序排序。
- 核心逻辑支持上下限、多个排序字段与升降序；未知统计不满足数值筛选，排序时总在末尾。
- 获取更多结果后，对累计结果重新排序；更改本地筛选不重新请求。
- 阅读虚构正文，切换暖纸/日间/夜间与字号。正文以文本节点渲染。
- Rust 宿主来自官方模板；CI 检查前端和 macOS Rust 编译。其他平台暂未验证。

## 下一阶段验收

1. **真实接入**：验证登录、搜索字段、分页边界、正文和系列接口；分别处理网络错误、登录过期、限流和作品不可访问。
2. **搜索会话**：获取、去重、过滤、排序；日期和匹配范围 UI；请求预算、取消、重试、自动补页；新查询取消旧请求，旧响应不得污染新结果。
3. **排序范围**：始终展示已获取/筛选后数量。不能将“无下一页”解释为已覆盖 Pixiv 全部作品，也不能把收藏数排序称为官方人气排序。获取足够展示的作品不代表获得全范围前 N 名。
4. **阅读**：获取正文后转为受控文档，保留注音、插图、分页和换行；系列目录与前后篇；按章节/段落/文字位置保存进度。
5. **排版**：字体、字号、行距、段距、宽度、背景；高级 CSS 独立阅读文档隔离，限制外部资源和应用接口访问，支持恢复默认。当前不接受任意 CSS。
6. **平台**：先验收桌面端；随后验证 Android / iOS 字体、长篇滚动和导航。不要把框架支持等同于应用已支持。

## 本轮不做

真实 Pixiv 登录和请求、预建作品库、公共数据分发、正文全文搜索/排除、图片/漫画浏览、下载管理、账号云同步、官方人气算法复刻。

## 校验

`npm run check`：条件分配、过滤/排序边界、去重、演示分页、类型与生产构建。
安装 Rust 后执行 `cargo check --manifest-path src-tauri/Cargo.toml`，或运行 `npm run tauri dev`。
